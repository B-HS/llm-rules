# 변경 검증

`docs/convention/ai-process.md`의 검증 사다리를 따릅니다.

1. `git status --porcelain`과 diff로 변경 범위를 확인합니다. 사용자가 지정한 경로가 있으면 그 범위로 한정합니다.
2. `package.json`과 lockfile을 읽고 프로젝트 패키지 매니저의 typecheck 스크립트를 우선 실행합니다. 없으면 설치된 로컬 `tsc --noEmit`을 사용합니다.
3. 설정된 lint·format 검사만 실행합니다. 새 검사기를 임의로 설치하지 않습니다.
4. 변경 파일에 대응하는 테스트를 찾고 관련 범위부터 실행합니다. 인터페이스 변경이면 소비 코드와 테스트의 동반 변경 여부를 확인합니다.
5. 가능하고 비용이 적절하면 빌드 또는 실행 스모크 확인을 수행합니다.

실패하면 핵심 오류의 파일·라인·테스트명을 적고 다음 단계로 넘어가지 않습니다. 실행하지 않은 검사는 생략 사유를 명시합니다. 검증 없이 통과했다고 보고하지 않습니다.
