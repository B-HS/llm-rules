방금 끝난 작업의 결과를 **ai-process §8(검증)·§9(결과물 저장·분류)** 에 따라 `docs/` 하위로 분류해 기록하세요. 각 기록은 **대상 파일 · 리포트 · 상세** 3부로 작성합니다.

인자: `$ARGUMENTS` (저장할 작업의 간단한 제목/맥락. 없으면 이번 세션의 직전 작업을 대상으로 한다.)

## 0. docs/ 보장

`docs/` 디렉토리와 분류 폴더가 없으면 만든다. (없을 때만 생성, 멱등)

- `docs/` 존재 확인: !`test -d docs && echo "docs/ 있음" || echo "docs/ 없음 → 생성 필요"`
- 분류 폴더: `docs/memory`, `docs/history`, `docs/bug`, `docs/acknowledge`, `docs/utils`

## 1. 무엇을 저장할지 판단

이번 세션에서 끝난 작업을 돌아보고, **어떤 분류에 기록할지** 결정한다. ai-process §9 표 기준:

| 경로 | 무엇을 넣나 |
|------|------|
| `docs/memory` | 장기 기억 — 결정·맥락·재사용 지식 (앞으로 항상 참고할 것) |
| `docs/history` | 작업 이력 — 무엇을 했는지 시간순 기록 |
| `docs/bug` | 버그 기록 — 증상·원인·해결 |
| `docs/acknowledge` | 인지·확인 사항 — 사용자 결정·합의·전제 |
| `docs/utils` | 작업에 쓴 보조 툴·util·스크립트 |

- **여러 분류에 해당하면 각각** 별도 파일로 남긴다 (예: 버그 수정 → `docs/bug` + `docs/history`).
- 어디에도 안 맞으면 사용자에게 1줄로 묻고 멈춘다. 추측해서 아무 데나 넣지 않는다.
- `docs/PROCESS.md` 가 있으면 끝난 체크리스트 항목을 `[x]` 로 갱신한다. (없으면 생략)

## 2. 각 기록은 3부 구성

파일명은 kebab-case. `history`/`bug` 등 시간순이 중요한 곳은 `YYYY-MM-DD-<제목>.md` 형식을 쓴다. 각 문서는 아래 3부를 **반드시** 포함한다.

```markdown
# <제목>

## 대상 파일
- 변경/관련 파일 경로 (필요 시 함수·라인)

## 리포트
- 무엇을 / 왜 그렇게 했는지 (배경 · 결정 · 트레이드오프 · 대안)

## 상세
- 구체 내용 (재현 절차·원인·해결, 합의 전제, 재사용 지식 등 분류에 맞게)
```

분류별 상세 항목 가이드:
- **bug**: 증상 → 원인(근본) → 해결 → 검증 방법.
- **acknowledge**: 사용자 발언/결정 → 그 이유 → 적용 범위(언제 따르나).
- **memory**: 재사용 지식·맥락 → 다음에 어떻게 활용하나.
- **history**: 한 일·바뀐 것 → 결과.
- **utils**: 도구/스크립트 위치 → 용도 → 사용법.

## 3. 검증 메모 (§8)

이번 작업을 어떻게 검증했는지(테스트·tsc·수동확인 등)와 결과를 **리포트**에 함께 적는다. 검증을 안 했으면 안 했다고 사실대로 적고, 필요한 검증을 `docs/quality-assurance` 체크리스트로 남길지 사용자에게 묻는다. 검증 안 된 "완료" 단언은 하지 않는다.
