# 변경 검증

`docs/convention/ai-process.md`의 위험 비례 검증 원칙을 따릅니다.

1. `git status --porcelain`과 diff로 변경 범위를 확인합니다. 사용자가 지정한 경로가 있으면 그 범위로 한정합니다.
2. 변경 위험과 직접 연결된 가장 작은 정적 검사와 기존 테스트를 선택합니다. 새 검사기를 임의로 설치하지 않습니다.
3. 상위 범위로 영향이 전파되거나 실질적 위험이 남을 때만 typecheck, lint·format, 빌드 또는 실행 확인을 추가합니다.

같은 변경 상태에서 성공한 검증은 명령·결과 증거를 재사용하고 다시 실행하지 않습니다. 실패 원인을 수정한 뒤에는 관련 검사만 한 번 재실행합니다. 같은 실패가 세 번 연속이면 반복을 중지하고 잘못된 가정과 진단 질문 하나를 보고합니다.

주 검증 뒤 남은 실질적 모호성만 edge-case worker에 맡깁니다. 지나치게 특수한 사례는 실행하지 않고 `docs/quality-assurance`에 테스트 부채로 남깁니다. 실행하지 않은 검사는 생략 사유를 명시하며, 검증 없이 통과했다고 보고하지 않습니다.
