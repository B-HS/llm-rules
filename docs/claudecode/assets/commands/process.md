`docs/PROCESS.md` 작업 체크리스트를 유지합니다. 인자(이번에 갱신하거나 추가할 작업, 비어 있을 수 있음): $ARGUMENTS

## 1. 현재 체크리스트 갱신

- `docs/` 가 없으면 만듭니다.
- `docs/PROCESS.md` 를 읽고 진행 중인 작업의 상태를 실제 진척에 맞춥니다. 끝난 항목은 `- [x]`, 나머지는 `- [ ]` 로 두고, 항목마다 무엇을 했는지 또는 다음에 무엇을 하는지 한 줄을 붙입니다.
- 요청 범위 안에서 완료에 필요한 항목이 새로 생겼으면 체크리스트에 추가하고 계속 진행합니다. 요청 범위를 넓히는 항목은 추가하지 않고 사용자에게 묻습니다.
- 대화 기록과 실제 파일이 다르면 파일을 기준으로 삼습니다.

## 2. 새 작업이면 체크리스트 생성

인자로 받은 작업이 기존 체크리스트에 없으면 새 섹션을 만듭니다. 작업을 스텝 단위로 나누고 항목마다 상세나 참조를 한 줄 적습니다.

```markdown
## 작업: <작업명> (진행 중)

<요청 한두 줄 요약>

- [ ] 1. <할 일> — <상세·참조>
- [ ] 2. <할 일> — <상세·참조>

기준 문서: <이 작업이 따르는 문서나 결정 기록>
```

작업이 끝나면 제목의 `(진행 중)` 을 `(완료)` 로 바꿉니다. 세션 시작 hook 이 이 표시로 활성 작업을 찾습니다.

## 3. 정리

- `PROCESS.md` 가 약 300줄을 넘으면 오래된 완료 섹션을 `docs/history/` 로 옮깁니다.
- 완료된 작업에 장기 결정, 사용자 합의, 버그 기록이 있으면 `/llm-rules:save-docs` 로 분류 저장합니다.
