# COMMENTS — 주석 컨벤션

> FE / BE 를 가리지 않고 **모든 코드베이스에 공통 적용**되는 주석 규칙이다.
> 핵심 원칙은 하나다. **"설명은 코드가 아니라 문서에 남긴다."**

---

## 1. 원칙 — 코드 안에는 주석을 넣지 않는다

> **코드 파일 내부에는 주석을 절대 작성하지 않는다.**

- 한 줄 주석(`//`), 블록 주석(`/* ... */`), JSX 주석(`{/* ... */}`), CSS 주석(`/* ... */`) 모두 작성하지 않는다.
- 코드는 **네이밍 · 구조 · 타입**으로 스스로 설명되게 작성한다. 주석으로 설명해야 할 정도면 먼저 코드를 고친다 (이름 변경, 함수 추출, 타입 명확화).
- 단, 아래 **2장(JSDoc)** 의 경우만 예외로 허용한다.

```typescript
// X — 코드 내 설명 주석
const d = u.createdAt // 가입일
// 가격이 0보다 크면 유료
if (price > 0) { ... }

// O — 주석 없이 이름과 타입으로 설명
const signupDate = user.createdAt
const isPaid = price > 0
if (isPaid) { ... }
```

---

## 2. 유일한 예외 — JSDoc

주석을 작성하는 **유일한 경우는 JSDoc 을 지원하기 위해서**다. (에디터 자동완성 · 호버 문서 · 공개 API 계약 표현)

### 2.1 사용 범위

- 라이브러리/패키지로 노출되는 **공개 API**, 재사용 유틸, 의미가 비자명한 함수 시그니처에 한해 `/** ... */` JSDoc 블록을 붙인다.
- 내부 구현 디테일을 설명하는 용도로는 쓰지 않는다. (그건 4장 → 문서로)

### 2.2 언어 — 기본 영어

- **JSDoc 은 기본적으로 영어로 작성한다.**
- 프로젝트가 **다국어(JSDoc 다국어 제공)** 를 필요로 하는 경우에는 **사용자에게 target language 를 먼저 확인**하고, 프로젝트에 **target lang 을 명시해 기록**한다 (예: `docs/jsdoc-lang.md` 또는 프로젝트 설정에 `jsdocLang: 'ko'`).

```typescript
// O — 공개 함수에 영어 JSDoc
/**
 * Builds a paginated response envelope.
 * @param data - page items
 * @param pagination - page metadata
 */
export const paginatedResponse = <T>(data: T[], pagination: Pagination) => ({ ... })
```

## 3. 그 외 모든 "설명하고 싶은 것" → `docs/` 로

코드에 남기고 싶었던 설명(왜 이렇게 짰는지, 트레이드오프, 임시 우회, 복잡한 비즈니스 규칙, TODO 의 맥락 등)은 **주석 대신 프로젝트의 `docs/` 디렉토리에 문서로 남긴다.**

- 프로젝트 루트에 `docs/` 폴더가 없으면 **생성한다.**
- 한 건의 설명은 아래 세 가지를 포함한다.

| 항목 | 내용 |
|------|------|
| **대상 파일** | 설명이 적용되는 파일 경로 (필요시 함수/라인) |
| **리포트** | 무엇을 / 왜 그렇게 했는지 (배경 · 트레이드오프 · 대안) |
| **상세 내용** | 원래 코드 주석으로 남기려던 구체적 설명 전문 |

### 3.1 문서 양식 (예시)

```markdown
# service/mail/sync.ts — 증분 동기화 커서 처리

## 대상 파일
- service/mail/sync.ts (`syncMail`)

## 리포트
IMAP UID 가 아니라 internalDate 기준 커서를 쓴다. UID 는 메일함
재생성 시 리셋되어 중복 동기화가 발생하기 때문. 대안(UID+UIDVALIDITY)
은 프로바이더별 편차가 커서 배제했다.

## 상세
- 커서는 마지막 성공분의 internalDate(ms) 를 저장한다.
- 동률(internalDate 동일) 메일은 messageId 로 2차 정렬해 누락을 방지한다.
```

---

## 4. 요약

| 상황 | 처리 |
|------|------|
| 코드 동작을 설명하고 싶다 | **하지 않는다.** 이름·구조·타입으로 표현 |
| 공개 API 시그니처 문서화 | **JSDoc (영어)** 만 허용 |
| JSDoc 다국어가 필요 | 사용자에게 target lang 확인 후 프로젝트에 명시 |
| 배경·이유·트레이드오프·복잡한 규칙 | 코드가 아니라 **`docs/`** 에 (대상 파일 · 리포트 · 상세) |
| `docs/` 폴더가 없다 | **생성**한다 |
