# 세션 핸드오프 준비

이 스킬은 문서와 재개 프롬프트만 만들며 애플리케이션 코드는 수정하지 않습니다.

1. 현재 대화와 작업 상태에서 최종 목표, 완료·진행·미착수 작업, 채택·기각 결정과 이유, 사용자 선호, 미해결 질문, 환경 전제를 목록화합니다.
2. `git status`, `git diff`, 필요 시 최근 log와 `docs/`를 대조해 문서의 경로·명령·API 주장이 실제 코드와 일치하는지 확인합니다.
3. 불일치를 해소하고 필요한 기록을 `docs/acknowledge`, `memory`, `history`, `bug`, `feedback`, `quality-assurance`에 저장합니다. 새 병렬 분류 체계를 만들지 않습니다.
4. `docs/HANDOFF.md`를 다음 내용으로 갱신합니다.
   - 프로젝트 정의와 현재 목표
   - 완료·진행·미착수 작업과 다음 한 줄
   - 채택·기각 결정과 상세 문서 링크
   - 사용자 방향성·작업 규칙
   - 미해결 질문
   - 환경·버전·실행 방법
   - 다음 세션 TODO와 관련 파일
   - 문서 지도
5. 인벤토리의 모든 항목이 문서에 존재하고 코드 참조가 실제와 일치하는지 항목별로 재검증합니다.
6. 새 세션이 `docs/HANDOFF.md`, 관련 문서, 진행 중 코드 파일을 순서대로 읽고 이해를 확인한 뒤 다음 작업을 시작하도록 하는 복사 가능한 재개 프롬프트를 출력합니다.

복기 신뢰도가 낮은 구간은 숨기지 말고 HANDOFF에 명시합니다. 대충 요약하거나 기각된 대안의 이유를 버리지 않습니다.
