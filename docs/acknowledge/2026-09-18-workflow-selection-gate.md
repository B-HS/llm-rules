# workflow 선택 게이트 합의

## 배경

기존 규칙은 도구를 사용하는 모든 실행 작업에 다중 에이전트 workflow를 강제했다. 사용자는 작업 성격과 세션 상황에 따라 workflow 사용 여부를 직접 선택하고, handoff나 `PROCESS.md`를 통해 새 세션에서 이어갈 때도 과거 선택이 자동 승계되지 않기를 요청했다.

## 결정

- 새 도구 사용 작업마다 실행 전에 workflow 사용 여부를 한 번 묻고 답을 기다린다.
- 선택은 현재 실행 작업에만 유효하다. 같은 작업의 후속 단계에서는 다시 묻지 않는다.
- 새 세션, resume, clear, compact, handoff, `PROCESS.md` 기반 재개에서는 같은 작업을 이어가더라도 한 번 다시 묻는다.
- 현재 요청에서 이미 선택했거나 workflow Skill·Command를 직접 호출했으면 중복 질문하지 않는다.
- workflow를 선택하지 않으면 main이 직접 수행하며, 문서·검증·보안·Git 등 나머지 규칙은 유지한다.
- 작업별 선택 자체는 장기 합의나 다음 세션 기본값으로 저장하지 않는다. handoff에는 재개 후 다시 질문하라는 계약만 남긴다.

## 이유

작업마다 병렬 위임의 이득과 오버헤드가 다르므로 사용자가 실행 방식을 선택할 수 있어야 한다. 선택 범위를 현재 작업으로 제한하고 재개 경계에서 다시 확인하면, 오래된 세션 결정이 새 컨텍스트에 묵시적으로 적용되는 문제도 막을 수 있다.

## 기각한 대안

- 모든 도구 작업에 workflow 강제: 사용자 선택권이 없고 단순 작업에도 위임 비용이 발생한다.
- 한 세션의 첫 선택을 모든 후속 작업에 적용: 같은 세션 안에서도 작업 성격이 달라질 수 있다.
- 이전 선택을 `PROCESS.md`나 `HANDOFF.md`로 영구 승계: 재개 시 사용자가 다시 선택해야 한다는 요구와 충돌한다.
